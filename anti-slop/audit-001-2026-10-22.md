# Antislop audit 001 · 2026-10-22

Scope: GPUI interface (`crates/app-gpui`, `crates/toolbar`), visible text, workspace
comments and documentation (`README.md`, `docs/`).

There is no `DESIGN.md`. The visual direction comes from the README («Editor · Entrada de notas»:
dark theme, ribbon, light sheet, inspector, transport). The dark theme is justified:
it is a creative tool for long sessions, with the light sheet as the only focal point.
It does not count as a finding.

Priority follows the rule's level: Hard Gate = HIGH, Purpose-Gate = MEDIUM,
Quality Locks = LOW. Nothing is touched until you choose numbers.

## What is fine

- No gradients, glow, blur, looping animations or side stripes. Shadows appear only on
  popup menus, modals and the sheet, where they mark elevation.
- No decorative emoji in the interface or in comments. The ones in tests are data.
- Comments: about 1,100 lines in 70,000 lines of Rust. Almost all of them explain a why,
  an invariant or a GPUI or audio trap. Fewer than 1 % are weak.
- No invented figures, testimonials or claims. The README describes what exists
  and marks what is pending.

## Findings

### HIGH

1. **R-25 · Placeholder of the text fields is invisible.**
   [text_input.rs:500](../crates/app-gpui/src/ui/text_input.rs) paints the placeholder
   with `hsla(0, 0, 0, 0.2)`, 20 % black on `FIELD 0x222329`: 1.09:1. It affects
   «Buscar comandos…» (Search commands…) and every field. Fix: use `MUTED 0x969ba7` (5.63:1).

2. **R-25 · Credits placeholder on the sheet: 2.12:1.**
   [ui.rs:1342](../crates/app-gpui/src/ui.rs) uses `0xb3ada3` on the paper `0xfbf9f3`.
   Fix: a warm grey of at least 4.5:1, such as `0x6f6a62`, that is told apart from the
   copyright `0x67635c` by size or italics.

3. **R-25 · Ribbon labels below AA.**
   `CAPTION 0x7d8291` on `CARD 0x1f2026`: 4.23:1 with 9–10 px text
   ([toolbar.rs:17-23](../crates/app-gpui/src/ui/toolbar.rs)). Fix: `0x8a8f9c`
   (5.02:1).

4. **R-25 · Page number on the sheet: 3.63:1.**
   `0x878277` on `0xfbf9f3` at 12 px × zoom ([paint.rs:224](../crates/app-gpui/src/paint.rs)).
   At the initial 70 % zoom it ends up at about 8 px. Fix: darken it above
   4.5:1. If the grey imitates print, that has to be confirmed first.

5. **R-32 · No control shows focus or can be reached with Tab.**
   The buttons are `div`s with `on_click`. `action()` ([ui.rs:133](../crates/app-gpui/src/ui.rs))
   returns focus to the canvas, and `TextInput` does not change its border on focus. The
   shortcuts and the search box (⌘F) cover almost every command, but not the time bar
   ([ui.rs:2352](../crates/app-gpui/src/ui.rs)), the sound chip (2315) or the click
   on the header (1297). Minimum fix: a visible focus border on `TextInput`, and
   add to the command search whatever only works with the mouse. Making the whole ribbon
   navigable with Tab is a separate, larger task.

6. **R-32 · Panel buttons without a name.**
   `toggle-instruments` and `toggle-inspector` ([ui.rs:390,401](../crates/app-gpui/src/ui.rs))
   are only an icon, with no tooltip or label, unlike the rest of the header.
   Fix: tooltip «Instrumentos (I)» / «Propiedades» with the current shortcut, like the others.

7. **R-26 · Pending items have no visible mark in the ribbon, and «TODO» as user-facing text.**
   The ribbon's pending controls carry only a dashed border
   ([toolbar.rs:158-160](../crates/app-gpui/src/ui/toolbar.rs)): the notice is
   only in the tooltip. Elsewhere the visible word is development jargon:
   `slider_placeholder(…, "TODO", …)` ([ui.rs:1718-1719](../crates/app-gpui/src/ui.rs)),
   the status message «TODO · Reproducción en bucle» (2205) and `todo_badge()` (155, 2329).
   The search and Preferences already say «Pendiente». Fix: use «Pendiente» everywhere,
   also as a visible mark in the ribbon. The README (line 79) talks about «TODO» and
   would have to follow the change.

8. **R-27 · Errors that give neither cause nor what to do.**
   «No hay audio disponible» ([playback.rs:282](../crates/app-gpui/src/playback.rs)),
   `Audio: {error}` ([ui.rs:2442](../crates/app-gpui/src/ui.rs)) and
   «Sin acción para «{}»» ([main.rs:1305](../crates/app-gpui/src/main.rs)). Fix: add
   the next step, for example «No hay salida de audio. Conecta un dispositivo y pulsa
   Reconectar audio en Sonidos». Good models that already exist:
   [comments.rs:111](../crates/app-gpui/src/ui/comments.rs) and [review.rs:50](../crates/app-gpui/src/ui/review.rs).

9. **R-02 · Em dashes (—) in comments and documentation.**
   - [ui/toolbar.rs:2](../crates/app-gpui/src/ui/toolbar.rs): the only case in comments.
   - [tools-and-integrations.md:1](../docs/tools-and-integrations.md) («Levare — Herramientas…») and :72.
   - [development.md:687](../docs/development.md): an aside set off with Spanish-style dashes
     («—el de menor prioridad…—»). It is correct punctuation in Spanish, so keeping it
     or removing it is your call.
   Left out: the tenuto glyph in
   [expression.rs:24](../crates/score-core/src/expression.rs), which is a musical symbol,
   and the titles of the examples in `score-io/examples`, which are content.

10. **R-02 · «—» as an empty cell in `docs/shortcuts.md` (98 times).**
    It comes from [keymap/src/docs.rs:33](../crates/keymap/src/docs.rs). Fix: leave the cell
    empty and regenerate with `LEVARE_UPDATE_SHORTCUTS=1 cargo test -p score-keymap`.

11. **R-02 · Em dash in the window title: «Partitura • — Levare».**
    [main.rs:2771](../crates/app-gpui/src/main.rs). That is the macOS convention for
    «document — app», so it is your call: keep it (I note it as an exception) or
    switch to «Partitura • · Levare».

### MEDIUM

12. **R-06 · Uppercase labels with no written reason.**
    «REPRODUCCIÓN» ([ui.rs:1717](../crates/app-gpui/src/ui.rs)), «PULSOS POR MINUTO · 20–400»
    (`tempo_editor.rs:44`) and the status «RESUELTO»/«PENDIENTE»
    ([comments.rs:141](../crates/app-gpui/src/ui/comments.rs)). In an inspector, all-caps
    section labels are a defensible convention, so the reason should be written down.
    On comment states they are unnecessary: «Resuelto» / «Pendiente».

### LOW

13. **R-29 / R-31 · There is no single theme.** The colours are spread across
    `ui.rs:34-41`, `ui/toolbar.rs:17-23`, `command_search.rs:5`, `playhead.rs` and
    `range_warning.rs`. Repetitions: `HOVER` = `ROW_HOVER` (`0x2c2e36`), `0x1d1e23` inline
    5 times, `0x3a3d46` and `0x3b3d46` as two nearly equal borders, and `0xa3a7b2` next to
    `MUTED`. There are four colours for the same warning: `0xf2b282`, `0xf1a4a4`, `0xffc47e`
    and `0xe69292`. The accent blue has 9 or more shades. `action()` and `ribbon_action()`
    are copies with hand-written colours. Fix: a `theme` module with named tokens
    (including a single `WARNING`) and a single button function.

14. **R-31 · Dots and marks that repeat what the text says.**
    «● Cambios sin guardar» / «✓ Guardado» ([ui.rs:2519-2521](../crates/app-gpui/src/ui.rs))
    and «● Escribiendo…» ([toolbar.rs:954](../crates/app-gpui/src/ui/toolbar.rs)). The tab
    dot (`ui.rs:367`) and the «•» in the title do mark a state without text, so they
    stay. «● Audición al escribir» marks on or off: it stays if the button
    has no other indicator.

15. **antislop-code · Comments that repeat the signature.**
    - [spec.rs:78](../crates/toolbar/src/spec.rs) «Switches something on or off.» (`Toggle`)
    - [spec.rs:80](../crates/toolbar/src/spec.rs) «Does something once.» (`Action`)
    - [shortcuts.rs:419](../crates/app-gpui/src/shortcuts.rs) (`without_keys`)
    - [part_view_tests.rs:1](../crates/score-layout/src/part_view_tests.rs): the reference
      to «plan 025», which will age badly.
    Only comments change; the code is not touched.

16. **C-5 · `docs/tools-and-integrations.md` out of date.** Line 30: «El proyecto aún no es
    un repositorio git» (The project is not yet a git repository; it is one). The table and the risks call `app-gpui`
    `partitura`, but its package is `levare`. In «Preguntas abiertas» (Open questions), the platform is already decided
    (macOS first, according to the README). Fix: correct the facts or mark the document
    as historical.

17. **C-3 · README order.** «Armónicos de cuerda» (string harmonics) comes after «Verificar» and
    «Alcance actual» (which holds the licences), as if it had been added
    at the end. Fix: move it next to «Pizzicato y arco» and leave «Verificar» and «Alcance actual» at the end.

## Dismissed

- Disabled controls with opacity 0.35–0.4 (≈ 1.9–2.1:1): WCAG 1.4.3 exempts inactive
  components.
- «→» in [spec.rs:792,863](../crates/toolbar/src/spec.rs): it indicates a real
  transformation (X → Y), it is not decoration.
- Section labels in tests (`// Piano: both staves.`): they help with orientation.
- Fixed dark theme: it has a reason (R-21).
