# Tuplets, double dots and sixty-fourths: implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let musicians write any common tuplet (duplets to nonuplets, with a free n:m
ratio), double-dotted values and sixty-fourth notes, and have them drawn, played,
saved, copied and exchanged through MusicXML like today's triplets.

**Why first:** it is the only gap on the way to the editing MVP that changes the
`.levare` format and the unit of time every crate uses. Every later feature (pickup
bars, voices 3–4, manual beams) builds on durations, so this goes in before them.

**Architecture:** Time stays integer ticks, with a finer resolution (`u32`,
645 120 ticks per whole note) that holds every supported value exactly. `Duration`
gains a dot count, a sixty-fourth value and an optional `Tuplet` ratio. As with today's
`triplet` flag, each event carries its own tuplet; groups are derived from consecutive
events, never stored. The four tick-indexed rhythm tables (rests, splits, divisi,
paste) become one decomposition on a coarse grid, so the finer resolution costs nothing.

**Tech Stack:** Rust 2024, GPUI `=0.2.2`, `serde`, `roxmltree` (MusicXML import).

## Where things stand

- `crates/score-core/src/duration.rs`: `TICKS_PER_WHOLE: u16 = 192`,
  `Duration { value, dotted: bool, triplet: bool }`, `NoteValue` from whole to
  thirty-second. 192 = 2⁶·3, so only factors of 2 and 3 divide exactly.
- Ticks are `u16` in about 80 places (`score-core`, `score-layout`, `score-io`,
  `score-text`, `app-gpui`, `agent-tools`); absolute positions are already `u64`.
- Triplet groups are inferred in `crates/score-layout/src/rhythm.rs:86` (runs of three
  equal triplet values). Beams treat them in `crates/score-layout/src/beaming.rs:147`
  and `:255`.
- Four dynamic-programming tables are indexed by tick: `event_move::notatable`
  (`crates/score-core/src/event_move.rs:280`), `divisi_rhythm_pieces`
  (`crates/score-core/src/divisi.rs:457`, a fixed 289-entry table), `RhythmPieces`
  in `crates/score-edit/src/clipboard.rs:235` and `:464`, and the MusicXML splitter
  (`crates/score-io/src/musicxml.rs:999`). At 645 120 ticks per whole they would be far
  too large.
- Ticks reach disk in two places: divisi change points
  (`Part::divisi_changes`, tick keys) in `.levare` (`SCHEMA_VERSION = 29`,
  `crates/score-io/src/lib.rs:28`), and `ClipEvent::offset` in the musical clipboard
  (version 6, `crates/score-edit/src/clipboard.rs`).
- Hard-coded tick numbers: `note_drag.rs:201` (quantum 12/8/6/4), clipboard
  `MAX_TICKS` (`3072`), the divisi table size, MusicXML `<divisions>` written as
  `TICKS_PER_QUARTER` (`musicxml.rs:501`).
- MusicXML import refuses anything but 3:2, more than one dot or values shorter than a
  thirty-second (`crates/score-io/src/musicxml/import.rs:1824`). Export writes
  `<time-modification>` but no `<tuplet>` brackets.
- The app toggles the triplet with `toggle_rhythm` (`crates/app-gpui/src/main.rs:2151`)
  and `Command::SetTriplet`. `⌘3` is bound to `duracion.tresillo`; `⌘2` and `⌘4`–`⌘9`
  are free.

## Design decisions

### D1. Resolution: 645 120 ticks per whole note, as `u32`

645 120 = 2¹¹·3²·5·7 = 256 · lcm(2…9). The smallest value, a double-dotted
sixty-fourth (7/256 of a whole), is a whole number of ticks, and still is after
dividing by any tuplet number from 2 to 9. A 16/1 bar is 10 321 920 ticks, well within
`u32`. Old ticks convert by multiplying by **3360** (645 120 / 192).

Rejected alternative: rational durations (numerator/denominator). They allow nested
tuplets, but every addition, comparison and table in the workspace would change. Nested
tuplets are out of scope; switching later is a migration of the same kind as this one.

### D2. The model

```rust
pub enum NoteValue { Whole, Half, Quarter, Eighth, Sixteenth, ThirtySecond, SixtyFourth }

pub struct Tuplet {
    pub actual: u8,      // 2..=9: notes written
    pub normal: u8,      // in the time of `normal` units
    pub unit: NoteValue, // the value the ratio counts
}

pub struct Duration {
    value: NoteValue,
    dots: u8,                // 0..=2
    tuplet: Option<Tuplet>,
}
```

- `ticks() = base · (2 − 2^−dots) · normal / actual`, computed in integers.
- A ratio is valid when `2 ≤ actual ≤ 9`, `normal ≥ 1`, `normal ≠ actual` and
  `actual/2 ≤ normal ≤ 2·actual`. That covers 2:3, 3:2, 4:3, 4:6, 5:4, 6:4, 7:4, 7:8,
  9:8… and keeps nonsense out.
- Default ratios, used by `⌘n`: 2:3, 3:2, 4:3, 5:4, 6:4, 7:4, 8:6, 9:8.
- `unit` counts the group: a 3:2 group of eighths spans three written eighths, the time
  of two. A quarter followed by an eighth in that group is valid. `unit` changes no
  event's ticks, only grouping and the bracket.
- `with_dotted(bool)`/`is_dotted()` stay as one-dot shorthands; new `dots()`,
  `with_dots(u8)`, `tuplet()`, `with_tuplet(Option<Tuplet>)`. `with_triplet` and
  `is_triplet` go once every caller is moved.
- `Duration::MIN_TICKS` and `MAX_EVENTS_PER_MEASURE` are derived with const fns from
  the supported set, not written by hand.

### D3. Groups are derived, with one invariant

`score_core::tuplet_groups(measure, voice) -> Vec<TupletGroup { start_tick, events, complete }>`
in a new `crates/score-core/src/tuplet.rs`: walking a voice, consecutive events with an
equal `Tuplet` add up their written length (the ticks they would last without the
ratio); a group closes when it reaches `actual × unit`, and the next equal event starts
a new one. An unfinished group at the end of the voice stays visible, as today.

**Invariant**, checked in `Score::validate` (`crates/score-core/src/lib.rs:852`): no
event extends past the end of its group, and no group crosses a barline. Old triplets,
migrated to `Tuplet { 3, 2, unit: own value }`, group exactly as `rhythm.rs` groups them
today (three equal values), so existing scores look the same.

Layout, beaming, MusicXML and editing all call this one function; `rhythm.rs` stops
inferring groups itself.

### D4. Editing rules

These generalize what Levare does today for triplets and follow Sibelius, whose
shortcuts Levare uses.

1. **Writing a tuplet value where no group is open** starts a group. The rest of its
   span is filled with rests of the same tuplet, so the next entry overwrites them and
   later music stays on the beat.
2. **Writing inside a group with the same tuplet** overwrites within it. A value that
   would pass the end of the group is refused: «La figura no cabe en el grupillo».
3. **Writing a plain value, or another tuplet, on a group's first event** replaces the
   whole group: its span is cleared and written as usual.
4. **Writing a plain value strictly inside a group** is refused: «Dentro de un grupillo
   solo caben sus figuras; empieza en su primera nota para sustituirlo».
5. **A group never crosses a barline** (today: «Un tresillo no puede cruzar la barra de
   compás», `overwrite.rs:88`), now for any ratio: «Un grupillo no puede cruzar la barra
   de compás».
6. **Gaps inside a group** (after a shorter value, delete, erase or move) are filled
   with rests of that group; gaps outside groups with plain values, as today.
7. **Changing a member's value or dots** keeps its tuplet; refused if it would pass the
   group's end.
8. **Removing a tuplet** (`SetTuplet(None)` with a group member selected) turns the
   whole group into plain rests of the same total length. Undo brings it back. This is
   the one destructive rule; it matches Sibelius when you delete a tuplet bracket.
9. **Dragging a member in time** snaps to the group's grid (the tick length of its
   unit in the ratio) and stays inside the group. Dragging a plain note into a group is
   refused.
10. **Paste** keeps durations. A group that would cross a barline at the destination
    makes the paste fail with rule 5's message, without changing the score.

### D5. Entry and commands

- The entry duration carries a tuplet, as it carries the triplet flag today, and stays
  on until it is pressed again.
- With a note, chord or rest selected, `⌘n` turns it into the first event of a new
  group whose unit is its value, filling the rest of the span with rests (rule 1).
  Pressing the same ratio again on a group removes it (rule 8).
- Command ids (Spanish, stable once published): keep `duracion.tresillo`; add
  `duracion.dosillo`, `duracion.cuatrillo`, `duracion.quintillo`, `duracion.seisillo`,
  `duracion.septillo`, `duracion.octillo`, `duracion.nonillo`, `duracion.grupillo`
  (*Otro grupillo…*), `duracion.semifusa`, `duracion.doble_puntillo`.
- Default shortcuts: `secondary-2`, `secondary-4` … `secondary-9` for the tuplets,
  as in Sibelius. The sixty-fourth and the double dot get no default key: in Sibelius
  they live on the second keypad layout, which Levare does not have. They can be
  assigned in Preferences, and the ribbon has them.
- Ribbon, **Escribir**: **Semifusa** joins the Duración track; **Doble puntillo**
  sits next to **Puntillo**; next to **Tresillo** a **Grupillos** dropdown lists
  2 to 9 and **Otro grupillo…**.
- **Otro grupillo…** opens an editor in the Selección tab, like the other editors, with
  two numbers (notes, in the time of) and **Aplicar**/**Cancelar**. The ratio rules in
  D2 are checked as you type.
- Labels: «Semifusa», «Negra con doble puntillo», «Corchea · quintillo (5:4)»; the
  status pill and the selection panel use `Duration::label`.

### D6. Files and clipboard

- `.levare`: `SCHEMA_VERSION` 30. The 29 → 30 migration multiplies the tick keys of
  `divisi_changes` by 3360. Durations need no migration step: the deserializer accepts
  the old `{value, dotted, triplet}` form (triplet → `{3, 2, unit: value}`) and the new
  `{value, dots, tuplet: {actual, normal, unit}}`; a plain value is still written as a
  bare string, so most events do not change on disk.
- Musical clipboard: version 7. The 6 → 7 step multiplies `ClipEvent::offset` by 3360;
  `MAX_TICKS` comes from `MAX_MEASURES` and the 16/1 capacity.
- Older Levare versions refuse version-30 files with the existing «newer version»
  error. That is the breaking change, and it gets a `BREAKING CHANGE:` footer.
- Recovery files share the envelope and the migration.

### D7. MusicXML

- Export: `<type>64th</type>`, one `<dot/>` per dot, `<time-modification>` with
  `actual-notes`, `normal-notes` and `normal-type` when the unit differs from the value,
  and `<tuplet type="start|stop" bracket="yes|no"/>` on a group's first and last event
  (`bracket` follows the layout's rule). `<divisions>` becomes the smallest value that
  makes every duration in the score a whole number (gcd of all event ticks), not 161 280.
- Import: accepts `64th`, up to two dots and any `time-modification` with a valid D2
  ratio; `normal-type` gives the unit, defaulting to the note's own type. Nested tuplets
  (two `<tuplet>` levels open at once) are refused, naming the bar: «MusicXML: grupillos
  anidados en el compás N».

### D8. Engraving and playback

- Layout draws the group number (`actual`), with the bracket rule unchanged; beams use
  `Boundary::Tuplet` from D3, and the subdivision unit at `beaming.rs:255` becomes the
  ticks of the group's unit in its ratio. Sixty-fourths get four beam levels and Bravura
  `flag64thUp`/`flag64thDown` (U+E246/U+E247) and `rest64th` (U+E4E9); the second dot is
  placed after the first.
- Playback needs no new logic: it already turns ticks into time through the constants.
  It gets tests.

## Out of scope

Nested tuplets; groups across barlines; dotted tuplet units (a 2:3 group counted in
dotted quarters is written with an eighth unit instead); 128ths and breves; showing
ratios as «3:2» or hiding a bracket by hand; swing.
