# Panels that make sense: implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make each Levare panel answer one question: left, what is in the score (parts and mix); right, what is selected and what to change about it; top, where am I.

**Architecture:** The logic of what to show is pulled out into pure functions without GPUI, with tests: the selection model (`ui/selection_view.rs`), the filtering and grouping of parts (`ui/parts_view.rs`) and the panel memory (`panels.rs`). The GPUI drawing is rewritten on top of them in `ui/instrument_panel.rs` (left), `ui.rs` (`inspector` and the strip) and `ui/mixer.rs`.

**Tech Stack:** Rust 2024, GPUI `=0.2.2`, `serde_json`.

**Spec:** [docs/superpowers/specs/2026-10-27-panels-design.md](../specs/2026-10-27-panels-design.md). Approved mockup: [docs/superpowers/specs/2026-10-27-panels-mockup.html](../specs/2026-10-27-panels-mockup.html).

## Global Constraints

- No new editing features: the panel's buttons run commands and actions that already exist (`AppView::run`, `Command`); removing a mark uses `Command::RemoveMark` or the equivalent existing command.
- No control stops being accessible: whatever leaves a panel is still in the ribbon, a menu, a key or the command search.
- Colors only from `crates/app-gpui/src/ui/theme.rs`; controls with the ribbon's grammar (`look` in `ui/toolbar.rs`: no background at rest, hover one step of tone, chosen `SELECT` + `SELECT_BORDER` + `ACCENT_TEXT`).
- Interface texts in Spanish, sentence case, no letter-spaced uppercase labels; identifiers in English.
- With 32 parts the interface stays smooth: no walking the whole score per frame to paint a panel.
- `cargo fmt --all --check`, `cargo test --workspace --locked` and `cargo clippy --workspace --all-targets --locked -- -D warnings` must pass.
- One commit per task (commits were in Spanish then), ending with `Co-Authored-By: <model> <noreply@anthropic.com>`.

## Review Focus

1. **Removing a mark from the panel** leaves the score as if it had been removed from the ribbon, is undone with ⌘Z and the panel updates. Test in Task 2.
2. **32 parts** with search, folded families and Mezcla mode: the panel does not overflow or scroll two screens. Test in Task 3 (model) and visual check in Task 5.
3. **An open editor** (key signature from the strip, clef from the ribbon) appears on the right even if the right panel was closed, and the parts list does not move. Test in Task 2.
4. **A damaged or missing `paneles.json`** starts with the defaults without an error. Test in Task 1.
5. **Transposing instrument note:** shows the written pitch large and the correct «Suena …». Test in Task 2.

### Task 1: Panel state and memory

**Files:**
- Create: `crates/app-gpui/src/panels.rs`, `crates/app-gpui/src/panels_tests.rs`
- Modify: `crates/app-gpui/src/ui.rs` (`UiState`: `inspector: &'static str` → `right: RightTab`; new `parts_mode`, `folded_families`, `parts_query`), places that use `ui.inspector`, `main.rs` (load at startup and save on change)

**Interfaces:**
- Produces:
  - `pub enum RightTab { Selection, Sound, Review }` with `label()` «Selección», «Sonido», «Revisión».
  - `pub enum PartsMode { List, Mix }`.
  - `#[derive(Serialize, Deserialize)] pub struct PanelMemory { show_parts: bool, show_right: bool, right: RightTab, parts_mode: PartsMode, folded: Vec<String> }` with `Default` (left and right open, Selección, Lista, nothing folded).
  - `pub fn load(path: &Path) -> PanelMemory` (missing or damaged → `Default`, no panic) and `pub fn save(path: &Path, memory: &PanelMemory) -> io::Result<()>` with atomic writing like `recientes.json`.
  - The app loads `paneles.json` (`app_paths::data_path("paneles.json")`) at startup and saves it when any of those fields changes.
  - Today's «Mezclador» and «Sonidos» tabs are mapped: opening the Mixer (command `MIXER`) switches the left panel to Mezcla; `SOUNDS` opens `RightTab::Sound`.

### Task 2: Right panel according to the selection

**Files:**
- Create: `crates/app-gpui/src/ui/selection_view.rs`, `crates/app-gpui/src/ui/selection_view_tests.rs`
- Modify: `crates/app-gpui/src/ui.rs` (`inspector`, `properties`, the `#score-readouts` strip), the editors that today live on the left (`ui/clef_picker.rs`, `key_picker`/`time_picker`/`signature_scope` in `ui.rs`, `ui/tempo_editor.rs`, `ui/staff_text.rs`, `ui/header_editor.rs`, and the place that injects them in `ui/instrument_panel.rs`)

**Interfaces:**
- Produces:
  - `pub enum SelectionView { Score(ScoreSummary), Note(NoteSummary), Rest(NoteSummary), Passage(PassageSummary), Editor(EditorKind) }` computed by `pub fn selection_view(score: &Score, editor: &Editor, open_editor: Option<EditorKind>) -> SelectionView`, without GPUI.
  - `ScoreSummary { title, subtitle, composer, key, time, tempo, bars, parts, duration }`.
  - `NoteSummary { part, bar, beat, voice, pitch: Option<String> (written), sounding: Option<String> (only if it transposes), duration, range_warning: Option<String>, marks: Vec<MarkRow> }`.
  - `PassageSummary { parts: Vec<String>, first_bar, last_bar, notes, marks: Vec<MarkRow> }`.
  - `MarkRow { label: String, glyph: …, bar: usize, remove: MarkRemoval }`, where `MarkRemoval` is what the ✕ runs: `Command::RemoveMark(MarkRef)` for note marks and the existing action that removes a connection (slur, hairpin, line) for those that start or end on the note.
  - `pub enum EditorKind { Clef, Key, Time, Tempo, Text, Lyric, Chord, ScoreInfo }`.
  - The Selección tab draws each case as in the mockup. The editors are drawn in the Selección tab (same content as today, without help paragraphs, which move to `hover_hint`), and opening one sets `show_right = true` and `right = Selection`. The left panel stops hosting them.
  - The strip: Compás, Tiempo | Tempo, Métrica, Tonalidad (they open their editor on the right) | Parte · Voz | selection summary; Tonalidad no longer opens the left panel.
  - Tabs on the right: a three-option selector on one line («Selección», «Sonido», «Revisión»), in the ribbon's track style.
- [ ] **Step 1: Tests** in `selection_view_tests.rs`:
  - `nothing_selected_summarises_the_score`: title, key signature, meter, bars and parts of the example `examples/cuarteto-en-sol.partitura`.
  - `a_note_lists_its_marks_with_their_removal`: a note with staccato, `mf` and the start of a slur → three `MarkRow`s; running each `remove` on an `Editor` removes that mark and `undo()` brings it back.
  - `transposing_part_shows_written_and_sounding`: B♭ clarinet with written D → `pitch` «Re …», `sounding` «Do …».
  - `a_passage_counts_its_notes_bars_and_marks`.
  - `an_open_editor_wins_over_the_selection`.
- [ ] **Step 2: Run** `cargo test -p levare selection_view`. Expected: FAIL.
- [ ] **Step 3: Implement** the model and the drawing; remove from Properties the controls that repeat the ribbon, the help paragraphs and the two «Pendiente» sliders.
